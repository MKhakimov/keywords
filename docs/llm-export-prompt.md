# Инструкция для LLM: генерация файла экспорта

Готовый текст, который можно передать языковой модели, чтобы она сгенерировала головоломку в формате файла экспорта. Полученный файл загружается через «Мои головоломки → Импорт JSON». Структура файла подробно описана в README, раздел «Импорт и экспорт JSON».

## Ограничения подхода

LLM плохо строит корректные сетки. Импорт заново проверяет каждую головоломку валидатором и решателем, поэтому неверная будет отклонена с причиной, но доля отклонённых, скорее всего, будет высокой. Типичные причины:

- **Слова не из словаря.** Подходят только нарицательные существительные в именительном падеже из частотного словаря НКРЯ (около 21 тыс. слов); модель этого списка не видит.
- **Неоднозначная расшифровка.** На маленькой сетке с малым числом пересечений решатель находит второе решение.
- **Ошибки в «бухгалтерии»:** длина массива клеток, координаты слов, нумерация.

Поэтому инструкция требует сначала нарисовать сетку текстом и проверить её, и только потом собирать JSON.

Надёжнее, когда LLM пишет только тексты (рубрику, заголовок, загадку, пояснение, ответ), а сетку строит генератор приложения: такие тексты вставляются в форму «Создать», и головоломка гарантированно проходит проверку.

## Советы

- Просите **одну головоломку за запрос**; несколько готовых записей можно склеить в один массив `items`.
- **`meta.id` должен быть новым UUID**, иначе импорт пропустит головоломку как уже существующую.
- **Отчёт об импорте** показывает причину отклонения (например, «"ПЕНКА" нет в словаре» или «Сетка допускает больше одной расшифровки»). Её можно вернуть модели с просьбой исправить сетку.

## Инструкция

````text
Сгенерируй файл экспорта головоломки «числовой кейворд» на русском языке в формате JSON.
Выведи только JSON, без пояснений и без markdown.

## Что такое кейворд
Кроссворд без вопросов: каждая буква зашифрована номером, одинаковые буквы — одинаковые номера,
разные — разные. Игрок восстанавливает буквы по повторам и пересечениям слов.

## Порядок работы (обязательно, сначала про себя, потом JSON)
1. Нарисуй сетку построчно текстом: буква — буквенная клетка, # — блок, . — пустая клетка вне сетки.
2. Выпиши все горизонтальные и вертикальные цепочки из 2+ букв подряд (между блоками, пустыми клетками и краем).
   Проверь каждую цепочку по правилам ниже. Если хоть одна не подходит — исправь сетку и проверь снова.
3. Назначь номера, отметь стартовое слово и ответ.
4. Только после этого собери JSON и сверь его с сеткой: длину массива клеток, координаты слов, номера.

## Правила сетки
- Буквы — заглавные А…Я, без Ё (Ё пиши как Е). Й и Ъ — обычные буквы.
- Каждая цепочка из 2+ букв подряд по горизонтали (слева направо) и по вертикали (сверху вниз) —
  обычное русское нарицательное существительное в именительном падеже единственного числа,
  длиной 3–8 букв, распространённое и известное (ДОМ, ОЗЕРО, ПОВАР, ЗАВОД).
  Нельзя: имена собственные, сокращения, жаргон, грубые слова, формы других падежей, глаголы, прилагательные.
  Исключение — только части ответа (см. ниже).
- Слова в сетке не повторяются.
- Каждая буквенная клетка входит хотя бы в одно слово; клетка может входить в слово только в одном направлении.
- Все буквенные клетки связаны между собой по сторонам в одну область.
- Чем больше клеток на пересечениях двух слов, тем лучше: без пересечений расшифровка неоднозначна.
  Рекомендуемый размер — от 9×9 до 13×13, блоков около 25–35%.

## Ответ на загадку
- 1–2 слова (части), каждое не короче 2 букв. Это ответ на загадку из текста.
- Каждая часть занимает целую вертикальную (или горизонтальную) цепочку: с обеих сторон — блок, пустая клетка или край.
- Части ответа могут быть не существительными (например, «омуте»), но все пересекающие их слова — по правилам выше.
- Клетки части ответа помечаются answerPart = номер части (1, 2).
- editorial.answer — ответ как фраза («тихий омут»); после перевода в заглавные буквы и замены Ё на Е
  он должен совпасть с частями, записанными через пробел.

## Номера (шифр)
- K = число разных букв в сетке. Номера 1…K, без пропусков; одна буква — один номер.
- Выбери стартовое слово — одно из слов сетки (не часть ответа), 4–7 букв, по возможности с разными буквами.
  Его разным буквам дай номера 1, 2, 3… в порядке появления в слове; остальным буквам — номера по порядку дальше, в произвольном порядке.
- Клетки стартового слова: given = true. Остальные клетки: given = false.
- givens — номера букв стартового слова, по возрастанию.

## Текст
- Заголовок — короткий, журнальный; можно с пропуском «…» на месте ответа.
- Загадка — понятная, с одним обоснованным ответом.
- Пояснение — абзац, который не раскрывает ответ напрямую.
- Не выдумывай цитаты, даты и факты; лучше пословицы, поговорки, игра слов, общеизвестное.

## Формат JSON
{
  "format": "keywords-export",
  "version": 1,
  "exportedAt": "<текущая дата-время ISO 8601>",
  "items": [
    {
      "puzzle": {
        "schemaVersion": 1,
        "meta": {
          "id": "<новый UUID v4, у каждой головоломки свой>",
          "title": "<как заголовок>",
          "theme": "<тема одним-двумя словами>",
          "difficulty": "easy" | "medium" | "hard",
          "language": "ru",
          "alphabet": "ru-32",
          "seed": 0,
          "createdAt": "<дата-время ISO 8601>"
        },
        "editorial": {
          "rubric": "<рубрика>", "heading": "<заголовок>", "riddle": "<загадка>",
          "explanation": "<пояснение>", "answer": "<ответ фразой>"
        },
        "illustration": {
          "src": "/illustrations/placeholder.png", "alt": "", "prompt": "<описание желаемой иллюстрации>",
          "placeholder": true
        },
        "grid": {
          "width": <W>, "height": <H>,
          "cells": [ ...ровно W×H клеток построчно: индекс = row × W + col... ]
        },
        "words": [ ...все цепочки сетки, включая части ответа... ],
        "answerParts": [ { "order": 1, "text": "<ЧАСТЬ>", "row": r, "col": c, "dir": "down" } ],
        "cipher": [ { "number": 1, "letter": "<БУКВА>" }, ... по возрастанию номеров ],
        "givens": [1, 2, ...]
      },
      "progress": {},
      "solved": false,
      "createdAt": "<как meta.createdAt>"
    }
  ]
}

Клетки:
- { "kind": "void" } — вне сетки;
- { "kind": "block" } — блок;
- { "kind": "letter", "letter": "Д", "number": 1, "given": true } — буквенная клетка;
  у клеток ответа добавь "answerPart": 1 (или 2).

Слова (words) и части ответа: row и col — клетка начала слова, считая с 0 сверху и слева;
dir = "across" (по горизонтали) или "down" (по вертикали). В words должна быть каждая цепочка сетки ровно один раз
и ничего лишнего.

## Финальная проверка перед выводом
- cells.length = width × height.
- Буква каждой клетки совпадает с буквой её номера в cipher.
- Каждое слово из words читается в сетке по своим координатам.
- Все цепочки сетки есть в words; нет слов вне цепочек; нет повторов.
- Номера 1…K подряд, все используются в сетке.
- answerPart стоит ровно на клетках частей ответа.
- У каждого номера из givens есть хотя бы одна клетка с given = true, и все клетки с given = true имеют номер из givens.
````
