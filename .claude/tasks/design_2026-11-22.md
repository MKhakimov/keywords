## Решения пользователя

- [x] Алфавит: 32 буквы А…Я без Ё; Ё нормализуется в Е; Й и Ъ — отдельные буквы. Алфавит задаётся конфигурацией.
- [x] Ключ внизу: только K ячеек — по числу различных букв в сетке. Фиксированный ключ на 32 ячейки — настройка.
- [x] Ответ: фраза из нескольких частей (ключи «1», «2» в референсе). Модель данных поддерживает N частей.
- [x] Иллюстрации: генерация — позже; пока используется шаблон `public/illustrations/placeholder.png`.
- [x] Словарь: OpenCorpora (CC BY-SA) + частотный словарь Ляшевской–Шарова (НКРЯ).

## Подтверждено референсом

- Сетка ~18×19, не прямоугольная: левый верхний угол (~7×5) занят иллюстрацией.
- Номер стоит в каждой белой клетке; одна буква — один номер.
- Розовые клетки — блоки-разделители без номеров.
- Слова читаются по горизонтали слева направо и по вертикали сверху вниз; встречаются клетки, проверяемые только в одну сторону.
- Стартовое слово ЗАПЕВ напечатано в сетке с номерами 1–5 и продублировано в ключе.
- Жёлтая колонка: два вертикальных сегмента, у них иконки ключей «1» и «2».
- Ключ: 1…31 и обрезанная на сгибе «3» — почти наверняка 32 ячейки.

## Предположения (не подтверждены)

- Жёлтая колонка содержит ответ (пропуск «…» в заголовке), ключи задают порядок частей.
- Номера 1…n отдаются буквам стартового слова, остальные — перестановка.
- Любая цепочка из 2+ белых клеток — слово словаря.

## Алгоритм (кратко)

1. Словарь: нарицательные существительные, им. п. ед. ч., без имён/топонимов/аббревиатур, длина 3–15 (2 — опционально), стоп-лист, белый список, частотность → сложность. Сборка скриптом в `public/dict/ru-nouns.v1.json`; индекс «позиция+буква → битовая маска».
2. Модель: клетки `void | block | letter`; слот = максимальная цепочка 2+ letter-клеток; каждый слот обязан быть словом.
3. Шаблон блоков: маска void, закреплённые слоты ответа, доля блоков ~20–28%, лимит длины слотов, связность, без белых областей 3×3.
4. Заполнение: CSP с возвратом, MRV, forward checking, приоритет тематических и частотных слов, без повторов слов, лимиты и рестарты с новым seed, перестройка шаблона, честная ошибка при неудаче.
5. Шифр: биекция K букв → 1…K; буквы стартового слова получают 1…n, остальные — перестановка по seed.
6. Единственность: независимый решатель (номера → буквы, all-different, слоты по полному словарю) ищет до 2 решений; при неоднозначности — выбор стартового слова/подсказок или перестройка. Каждый номер встречается ≥2 раз.
7. Валидатор `validatePuzzle` — независимый, пишется до генератора; статус `valid` только при прохождении всех проверок из `CLAUDE.md`.

Генерация детерминирована (seed). LLM только предлагает тексты и тематические слова; слова проходят через словарь.

## Архитектура

Vite + React + TypeScript (strict) + SCSS Modules + Vitest, pnpm.

- `src/core` — чистый TS: алфавит, словарь, сетка, заполнение, шифр, решатель, валидатор, сборка головоломки, проекции play/editor.
- `src/worker` — генерация в Web Worker.
- `src/content` — провайдеры текстов и иллюстраций (LLM через серверный прокси позже, ручной ввод сразу).
- `src/storage` — схема JSON с версией, IndexedDB, импорт/экспорт.
- `src/ui` — SVG-сетка, ключ, страница, режимы игры/редактора/печати.
- `scripts/build-dictionary.ts`, `server/` (позже).

Игровой режим получает только проекцию `toPlayView(puzzle)` без букв и шифра.

## Риски

- Плотная сетка не заполняется → одиночные проверки, лимит длины слотов, рестарты, замеры на этапе 3.
- Долгий решатель единственности → поиск до 2 решений, тайм-аут = невалидно.
- Странные слова → частотный порог, стоп-лист.
- Факты от LLM → пометка «требует проверки».
- Лицензия CC BY-SA → атрибуция, словарь под той же лицензией.
- Шаблонная иллюстрация — репродукция чужой картины: только для локальной разработки, не для публикуемых головоломок.
