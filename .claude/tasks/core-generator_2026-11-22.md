# Ядро генерации: каркас, словарь, модель, валидатор, заполнение, шифр (этапы 0–4)

Статус: завершено
Свет: 🟢 зелёный

Основа — проектное решение `design_2026-11-22.md`. Цель задачи: рабочее ядро без UI, которое строит валидную головоломку из словаря и доказывает её корректность тестами.

## Требования

- Чистый TS в `src/core`, без зависимости от React/DOM.
- Детерминированность по seed.
- Валидатор независим от генератора и пишется раньше него.
- Ответ — N частей в закреплённых слотах (по умолчанию одна вертикальная колонка с двумя сегментами, как в референсе).
- Иллюстрация на этом этапе не нужна; шаблон `public/illustrations/placeholder.png` используется на этапе 5.

#### Результаты экспериментов с построчным перебором (отброшен)

Подход: обход клеток по строкам, в каждой клетке — буква или блок; блоки рождаются в процессе поиска.

| Вариант | 18×19 с вырезом 7×5 | 12×12 |
|---|---|---|
| Простой откат | 0/10 (лимит 200k узлов × 30 попыток) | — |
| + CBJ (прыжок к виновнику), слова ≤ 9 | 0/10, застревает на 4–6-й строке | 3/5 |
| + точная проверка строки наперёд (DP по префиксному дереву) | 0/20, попытка ~20 с | — |

Причина: верхние строки получают длинные вертикальные префиксы (МОНУМЕ…, ЗАРУБ…), которые жёстко задают буквы ниже; построчный поиск не видит этого заранее. Все неудачи — по лимиту, а не по исчерпанию (CBJ лишнего не отсекает).

Словарь: 21 тыс. существительных, из них 3 буквы — 385, 4 буквы — 1221; мало для плотной сетки.

Варианты:
- A. Заполнение по слотам на заранее сгенерированном шаблоне (классический CSP: MRV, forward checking по битсетам) с бо́льшим числом клеток, проверяемых в одну сторону.
- B. Расширить словарь (зеркало OpenCorpora / pymorphy3-dicts, викисловарь).
- C. Для MVP уменьшить сетку (13×13–15×15) и/или плотность.

### Этап 4. Шифр и единственность
- [x] Назначение номеров: буквы стартового слова — 1…n, остальные — перестановка по seed (`cipher/assign.ts`)
- [x] Решатель единственности (`solver/uniqueness.ts`): номера → буквы, all-different, согласованность слов по полному словарю, распространение до неподвижной точки, поиск до 2 решений, тайм-аут; части ответа не обязаны быть в словаре
- [x] Подбор стартового слова (длина по уровню сложности), сверка найденной расшифровки с шифром
- [x] Порог «номер встречается ≥ N раз» по умолчанию 1: в каждой сетке 3–6 букв встречаются однократно, а единственность доказывает решатель. Порог остаётся настройкой
- [x] `toPlayView` + `toCipherInput`: решатель получает только игровую проекцию. Отдельный `toEditorView` не нужен — редактор работает с `Puzzle`
- [x] Конвейер `generatePuzzle`: ответ → словарь по сложности (easy ≥10 ipm, medium ≥2, hard ≥0.5) → сетка → шифр → решатель → валидатор
- [x] Адаптивная плотность шаблона: с каждой неудачной попыткой `densifyChance` снижается
- [x] Приёмка: `tests/generatePuzzle.test.ts` (30 головоломок, отсутствие утечек в игровой версии, детерминизм); стресс-прогон 300/300 по трём уровням, медиана 60–140 мс, максимум 668 мс
