# Кейворды

Генератор журнальных числовых кейвордов на русском языке. Приложение строит головоломку из настоящих слов, доказывает, что её можно расшифровать единственным образом, и показывает её как журнальную страницу: можно решать в браузере, смотреть редакторскую версию и печатать в PDF.

Образец композиции — фотография журнальной страницы в `reference/magazine-codeword-reference.webp`. Полное техническое задание — в `CLAUDE.md`, история решений — в `.claude/tasks/`.

## Быстрый старт

```bash
pnpm install
pnpm dev          # приложение на http://localhost:5173
pnpm test         # тесты (Vitest)
pnpm typecheck    # проверка типов
pnpm lint         # ESLint
pnpm build        # production-сборка в dist/
pnpm dict:build   # пересобрать словарь из исходника (см. «Словарь»)
```

Требуется Node.js 22+ и pnpm.

## Игра

### Что такое числовой кейворд

Это кроссворд без вопросов. В каждой белой клетке стоит номер, и каждый номер обозначает одну букву: одинаковые буквы — одинаковые номера, разные буквы — разные номера. Игрок восстанавливает соответствие «номер → буква» по повторяющимся буквам и пересечениям слов. Найденные буквы вписываются в сетку и в ключ под ней.

### Как устроена страница

- **Рубрика и заголовок** — крупный заголовок, часто с пропуском «…» на месте ответа.
- **Загадка и пояснение** — короткий текст над сеткой, который подводит к ответу, но не раскрывает его.
- **Иллюстрация** — стоит в вырезе левого верхнего угла сетки.
- **Сетка** — белые клетки с номерами, розовые клетки-блоки разделяют слова.
- **Жёлтая колонка** — в ней спрятан ответ на загадку. Иконки ключей с цифрами «1», «2» показывают начало частей ответа и порядок их чтения.
- **Стартовое слово** — одно слово сетки напечатано открытыми красными буквами; его буквы имеют номера 1…n и уже вписаны в ключ.
- **Ключ** — полоса внизу: номер и пустая ячейка для буквы.

### Как играть в приложении

| Действие | Как |
|---|---|
| Выбрать клетку | щелчок по клетке |
| Сменить направление (по горизонтали / по вертикали) | повторный щелчок по той же клетке |
| Вписать букву | набрать на клавиатуре; буква встаёт во все клетки с этим номером и в ключ |
| Перейти к соседней клетке | стрелки (блоки пропускаются) |
| Стереть | Backspace / Delete |
| Проверить | кнопка «Проверить» — подсвечивает неверные номера и считает незаполненные |
| Начать заново | кнопка «Начать заново» — остаются только стартовые буквы |

Одна буква не может стоять у двух номеров: если вписать букву, которая уже есть у другого номера, она снимется с прежнего. Стартовые буквы изменить нельзя.

### Вкладки

- **Создать** — форма: рубрика, заголовок, загадка, пояснение, ответ, тема, сложность, размер сетки, seed, иллюстрация.
- **Мои головоломки** — все созданные головоломки с прогрессом; открыть в игре или редакторе, удалить, экспортировать в JSON (одну или все) и импортировать файл экспорта.
- **Игра** — интерактивное решение. Прогресс сохраняется автоматически.
- **Редактор** — решённая страница, ответ и его координаты, отчёт всех проверок, таблица шифра, список слов с координатами и направлениями.
- **Печать / PDF** — печатается чистая игровая страница A4 со стартовыми буквами, без интерфейса.

## Механика и правила

- **Алфавит** — 32 буквы А…Я без Ё. Ё при нормализации заменяется на Е; Й и Ъ — отдельные буквы. Алфавит задаётся конфигурацией.
- **Слова** — нарицательные существительные в именительном падеже. Любая цепочка из двух и более белых клеток подряд (по горизонтали или вертикали) обязана быть словом из словаря. Слова в сетке не повторяются.
- **Одиночные клетки** допустимы: клетка может входить в слово только в одном направлении. Клетка, не входящая ни в одно слово, недопустима.
- **Длина слов** — от 3 до 8 букв.
- **Ответ** — одно или два слова, каждое не короче двух букв. Части ответа стоят в жёлтой колонке сверху вниз, над каждой частью блок с иконкой ключа. Части ответа не обязаны быть словарными существительными (это может быть, например, «омуте»), но все пересекающие их горизонтальные слова — словарные.
- **Нумерация** — номера идут подряд 1…K, где K — число разных букв в сетке. Буквы стартового слова получают 1…n, остальные номера — перестановка по seed. Ключ показывает K ячеек.
- **Однозначность** — головоломка выдаётся только если по номерам, стартовым буквам и словарю расшифровка единственна (см. «Гарантии корректности»).

### Уровни сложности

| Сложность | Слова в сетке | Длина стартового слова | Открытых букв в среднем |
|---|---|---|---|
| Лёгкая | частотность ≥ 10 на млн (~3 700 слов) | 5–7 | ~7 |
| Средняя | частотность ≥ 2 на млн (~10 000 слов) | 4–6 | ~6 |
| Сложная | частотность ≥ 0,5 на млн | 3–5 | ~5 |

### Размер сетки

По умолчанию 18×19 с вырезом 7×5 под иллюстрацию, колонка ответа — 17-я (индекс 16). В форме размер меняется от 12×12 до 24×26; вырез и колонка ответа пересчитываются пропорционально. Колонка ответа всегда чётная по индексу, чтобы совпадать с решёткой шаблона.

## Как строится головоломка

Конвейер `generatePuzzle` (`src/core/puzzle/generatePuzzle.ts`):

1. **Ответ** нормализуется и разбивается на части.
2. **Словарь** фильтруется по уровню сложности.
3. **Раскладка** (`fill/layout.ts`): маска выреза, части ответа в колонке с блоками над и под каждой частью.
4. **Шаблон блоков** (`fill/template.ts`): британская решётка — блоки в клетках с нечётными номерами строки и столбца, поэтому около половины клеток проверяются только в одном направлении. Длинные цепочки режутся дополнительными блоками только там, где клетка и так проверяется в одну сторону, без сплошных полос блоков. Затем часть блоков случайно превращается обратно в буквы (уплотнение), если получившиеся цепочки допустимой длины.
5. **Заполнение** (`fill/fillSlots.ts`): перебор по словам — сначала самое стеснённое место (MRV), после каждого слова проверка пересекающих мест по битовым маскам словаря, без повторов слов, лимит шагов и перезапуски. С каждой неудачной попыткой шаблон становится реже, поэтому маленький словарь тоже успевает заполнить сетку.
6. **Шифр и стартовое слово** (`cipher/assign.ts`): номера назначаются, перебираются кандидаты в стартовые слова.
7. **Решатель** (`solver/uniqueness.ts`) проверяет однозначность расшифровки; найденное решение сверяется с шифром.
8. **Валидатор** (`validate/validatePuzzle.ts`) прогоняет все проверки. Если что-то не прошло, перебираются следующие варианты; если не удалось ничего, возвращается понятная ошибка, а не головоломка.

Генерация детерминирована по seed: тот же seed и те же параметры дают ту же головоломку. Типичное время — 60–140 мс, худший замеренный случай — около 0,7 с.

## Гарантии корректности

### Валидатор

Независим от генератора и проверяет готовую головоломку по 15 пунктам:

- размеры сетки и массив клеток согласованы;
- все буквы из выбранного алфавита;
- каждая буквенная клетка входит хотя бы в одно слово;
- сетка связна;
- каждая цепочка из 2+ букв — слово из словаря или часть ответа;
- список слов совпадает с клетками сетки;
- каждой цепочке соответствует ровно одно слово из списка;
- слова не повторяются;
- одна буква — один номер, один номер — одна буква;
- номера клеток согласованы с таблицей шифра;
- номера идут подряд от 1 до K;
- каждый номер встречается в сетке не реже заданного порога (по умолчанию 1);
- ответ размещён в сетке по частям;
- стартовые подсказки согласованы с сеткой и ключом;
- расшифровка единственна.

Головоломка считается готовой, только если пройдены все пункты; проверка без решателя помечается как пропущенная, и такая головоломка не считается готовой.

### Решатель единственности

Решает головоломку так, как её видит игрок: получает только игровую проекцию (номера, стартовые буквы, позиции частей ответа) и полный словарь — букв решения он не видит. Номера — переменные, буквы — значения, все номера получают разные буквы, каждое слово (кроме частей ответа) должно совпасть со словарным. Ограничения распространяются до неподвижной точки, затем идёт перебор с выбором номера с наименьшим числом вариантов. Ищется не больше двух решений; при превышении лимита результат — «не уложился», и головоломка отклоняется.

Однозначность доказывается относительно нашего словаря. Решатель использует полный словарь, а заполнение — отфильтрованный по сложности, поэтому проверка строже генерации.

## Архитектура

Стек: Vite 8, React 19, TypeScript 6 (strict), SCSS Modules, SVG для сетки, Vitest, ESLint. Tailwind не используется.

```
src/
  core/          чистый TypeScript без React и DOM (запрет импорта закреплён в ESLint)
    alphabet.ts      алфавит и нормализация
    rng.ts           детерминированный генератор случайных чисел
    dictionary/      загрузка словаря, индекс «позиция + буква → битовая маска»
    grid/            модель сетки, слоты, разбор и печать сетки из строк
    fill/            раскладка, шаблон, заполнение по словам, generateGrid
    cipher/          нумерация и стартовое слово
    solver/          решатель единственности
    validate/        валидатор и отчёт
    puzzle/          модель Puzzle, сборка, проекции, конвейер generatePuzzle
  worker/        генерация в Web Worker, клиент и протокол сообщений
  storage/       сохранение в IndexedDB
  ui/            компоненты: create, play, editor, library, puzzle (SVG), game (логика ввода)
  app/           корневой компонент и вкладки
scripts/         сборка словаря
data/dictionary/ стоп-лист и белый список
public/          словарь (dict/) и шаблонная иллюстрация
tests/           интеграционные тесты: словарь, генерация, хранилище
```

### Модель данных

- **`Puzzle`** (`src/core/puzzle/types.ts`) — полная головоломка: метаданные (id, тема, сложность, алфавит, seed), редакционный текст с ответом, иллюстрация, сетка (клетки `void | block | letter` с буквой, номером, признаком стартовой буквы и номером части ответа), слова с координатами и направлениями, части ответа, шифр, стартовые номера, отчёт валидации. Хранится отдельно от отрисовки.
- **`PlayView`** (`src/core/puzzle/views.ts`) — игровая проекция: без букв (кроме стартовых), без ответа, шифра и списка слов. Игровой режим и решатель получают только её, поэтому показать решение игроку невозможно даже случайно.

### Интерфейс

- Сетка рисуется одним SVG; иллюстрация вписывается в вырез, иконки ключей — в блоки над частями ответа.
- Ввод: скрытое поле `<input>` получает клавиатуру, SVG только отображает.
- Логика игры — чистый редьюсер (`ui/game/gameState.ts`) с тестами.
- Генерация идёт в Web Worker, словарь загружается из `public/dict/` один раз.
- Печать: отдельная чистая игровая страница всегда есть в разметке, но видна только при печати; `@page A4`, `window.print()` даёт векторный PDF.
- Шрифты с кириллицей хранятся локально через `@fontsource`: Lobster (заголовки), PT Sans (текст и номера).

### Хранение

IndexedDB, база `keywords`, два хранилища:

- `puzzles` — головоломка целиком (вместе с загруженной картинкой в виде data URL);
- `progress` — вписанные буквы и признак «решено».

Прогресс хранится отдельно, чтобы на каждую введённую букву не переписывать запись головоломки, которая может весить мегабайты. Записи имеют версию схемы и проверяются при чтении; повреждённые пропускаются. Если IndexedDB недоступен (например, в приватном режиме), приложение работает без сохранения и показывает предупреждение. Данные живут только в этом браузере — для переноса и резервных копий есть импорт и экспорт.

### Импорт и экспорт JSON

Файл экспорта (`src/storage/exchange.ts`):

```json
{
  "format": "keywords-export",
  "version": 1,
  "exportedAt": "2026-11-22T12:00:00.000Z",
  "items": [{ "puzzle": { "…": "…" }, "progress": { "7": "А" }, "solved": false, "createdAt": "…" }]
}
```

- Головоломка экспортируется целиком, вместе с загруженной картинкой (data URL), поэтому файл самодостаточный. Отчёт валидации в файл не пишется.
- При импорте (`src/storage/importPuzzles.ts`) сначала проверяется структура файла и каждой записи, затем каждая головоломка **заново проходит валидатор и решатель** в Web Worker: файл мог быть изменён вручную, а непроверенные головоломки не показываются.
- Головоломка с уже существующим id пропускается — сохранённая версия и её прогресс не перезаписываются.
- Прогресс из файла очищается от несуществующих номеров и мусора.
- После импорта показывается отчёт: что добавлено, что пропущено и что отклонено с причинами.

## Ключевые решения

1. **Сетку строит алгоритм, а не LLM.** Корректность доказывается валидатором и решателем; любые внешние генераторы (тексты, картинки) не касаются сетки.
2. **Решётка + заполнение по словам.** Сначала пробовался перебор клеток по строкам с выбором «буква или блок» (с прыжками к источнику конфликта и проверкой строки наперёд): ни одной сетки 18×19 на нашем словаре. Причина — длинные вертикальные префиксы из верхних строк. Решётка с клетками, проверяемыми в одну сторону, плюс перебор по словам заполняет 300 из 300 головоломок.
3. **Словарь — частотный словарь НКРЯ.** OpenCorpora недоступен (сайт не отдаёт выгрузки). Используется 21 тыс. существительных; частотность задаёт сложность. Стоп-лист и белый список ведутся вручную.
4. **Однозначность проверяет решатель, а не эвристика.** Правило «каждый номер встречается хотя бы дважды» снижено до одного раза: в каждой сетке 3–6 букв встречаются однократно, но решатель подтверждает однозначность. Порог остаётся настройкой.
5. **Игровая проекция как граница доступа.** Игра и решатель работают с `PlayView`, редактор — с `Puzzle`.
6. **Колонка ответа и иконки ключей.** Назначение жёлтой колонки и ключей выведено из референса (ответ на пропуск в заголовке, порядок частей) и сделано настраиваемым: позиция колонки и число частей задаются параметрами.
7. **TypeScript 6, а не 7** — `typescript-eslint` пока не поддерживает TypeScript 7.
8. **Печать средствами браузера** — векторный PDF без растеризации и без серверного рендера.

## Ограничения и что не сделано

- Тексты (загадка, заголовок, пояснение) пишутся вручную; генерации через LLM нет.
- Иллюстрации загружаются файлом; по умолчанию стоит шаблонная картинка `public/illustrations/placeholder.png` — это репродукция чужой картины, она только для разработки и не должна попадать в публикуемые головоломки.
- Мобильная вёрстка не приоритетна и не проверялась.
- Сетка регулярнее журнального образца: заметна решётка.
- Тема головоломки на подбор слов в сетке не влияет.
